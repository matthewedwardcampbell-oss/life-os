Radial / Circular layout ★
Not a file format — a layout, and the one Life OS leans on. Root at the center, branches fan out in a ring (like the map up top). Most legible at a glance, and the most on-brand (everything circle-centered).
Best for: at-a-glance overviews, the home shape, radial navigation. Renders from: any tree below — JSON/Markdown/OPML — same data, just drawn in a circle. Build it with d3's radial tree, markmap, or hand-rolled SVG like the hero above.
Nested JSON .json
The web lingua franca — a node with children. Trivial to read/write in JS.
{"text":"Root","children":[
  {"text":"Child A"},
  {"text":"Child B","children":[{"text":"leaf"}]}
]}
Best for: anything built in the browser (Life OS itself). Maps: text→t, children→nodes — basically already Life OS's shape.
Markdown / Markmap .md
Indented headings & lists = a tree. Git-friendly, hand-writable, renders to a live mind map with markmap.js. (Your Paracosm mind map is this.)
# Root
## Child A
- point 1
## Child B
  - nested leaf
Best for: text-first capture, version control, docs. Maps: heading/bullet depth→nesting, line text→t.
OPML .opml · XML
The near-universal outline interchange — almost every outliner/mind-mapper reads it.
<opml version="2.0"><body>
  <outline text="Root">
    <outline text="Child A"/>
    <outline text="Child B"/>
  </outline>
</body></opml>
Best for: moving outlines between apps. Maps: text attr→t, nested <outline>→nodes.
FreeMind / Freeplane .mm · XML
The classic desktop mind-map format. Rich: icons, links, notes, folding.
<map version="1.0.1">
  <node TEXT="Root">
    <node TEXT="Child A"/>
    <node TEXT="Child B"/>
  </node>
</map>
Best for: heavyweight mind mapping, importing legacy maps. Maps: TEXT attr→t, nested <node>→nodes.
Mermaid mindmap text
Code-driven diagram you can drop in any markdown/doc; indentation = hierarchy.
mindmap
  root((Root))
    Child A
    Child B
      leaf
Best for: embedding a map inside docs/README, code-first. Maps: indent depth→nesting, label→t.
XMind .xmind · ZIP
Full-featured desktop app. The file is a ZIP — modern XMind stores content.json (older: content.xml) of topics + children. Not hand-editable, but exports to OPML/Markdown/FreeMind.
// inside the .xmind zip: content.json
[{"rootTopic":{"title":"Root",
  "children":{"attached":[
    {"title":"Child A"},{"title":"Child B"}]}}}]
Best for: polished desktop maps. Tip: export to OPML/MD first, then import — easier than parsing the zip.
GraphViz DOT .dot / .gv
For graphs, not just trees — nodes can link to many nodes (great for faction webs, tech trees, relationships).
digraph {
  Root -> "Child A";
  Root -> "Child B";
  "Child A" -> "Child B";  // cross-link
}
Best for: non-tree relationships, your Paracosm faction/tech webs. Maps: edges→links (beyond strict parent/child).
Indent / CSV .txt / .csv
The simplest capture — tabs (or commas for level) define depth. Great for a quick brain-dump or a spreadsheet.
Root
	Child A
	Child B
		leaf
Best for: fast capture, importing from Sheets/Notes. Maps: tab depth→nesting, line→t.
For Life OS builds: the three that import/export cleanest with the least code are Nested JSON (native), Markdown/Markmap (what you already use for Paracosm), and OPML (universal). DOT is the one to reach for when a build needs real cross-links, not just a tree. XMind files are best converted to OPML/MD before import.
